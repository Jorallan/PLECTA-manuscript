\section{Results}
\label{sec:results}

This section first validates FilaSeg's instance-grouping performance on the
predefined synthetic evaluation set. It then examines sensitivity to the input
mask representation and synthetic scene properties, before presenting the
single real SEM development case study.

The primary quantitative comparison uses the method-independent centreline
fragments and equivalent one-pixel instance representations defined in
Section~\ref{sec:mm-f1}. Confidence intervals for overall results use
density-stratified scene resampling, while differences between methods are
paired within each scene. Stage~4 width rendering and the connected-component
lower-bound check are treated as secondary analyses.

\subsection{Validation of FilaSeg instance grouping}
\label{sec:res-density}
\label{sec:res-baselines}
\label{sec:res-representation}
\label{sec:res-qualitative}

FilaSeg was compared with the minimum-turn skeleton tracer on
\LockedSceneCount{} independently seeded synthetic scenes. Both methods
received the same degraded binary filament-axis mask for each scene, and their
outputs were evaluated using the same elementary centreline fragments.

\paragraph{Quantitative comparison.}

FilaSeg Stage~3 achieved a mean common-fragment
\Fone{}=\LockedFilaSegCommonFOneMean{} with a density-stratified 95\%
bootstrap confidence interval of
[\LockedFilaSegCommonFOneCILow{},
\LockedFilaSegCommonFOneCIHigh{}]. Its mean pairwise precision and recall were
\LockedFilaSegCommonPrecisionMean{} and
\LockedFilaSegCommonRecallMean{}, respectively.

Table~\ref{tab:locked} and Figure~\ref{fig:density} summarize the comparison
with the minimum-turn tracer.

The paired FilaSeg-minus-minimum-turn difference was
\FilaSegMinusBaselineSkeletonCommonFOneMean{}, with a 95\% confidence interval
of
[\FilaSegMinusBaselineSkeletonCommonFOneCILow{},

\subsection{Sensitivity to input-mask and synthetic scene properties}
\label{sec:res-mask}
\label{sec:res-width}
\label{sec:res-clean}

The following analyses examine how FilaSeg responds to changes in the
representation supplied to the algorithm. These experiments use development
data and are therefore interpreted as sensitivity analyses rather than
independent validation.

\paragraph{Axis-mask width.}

The effect of the binary filament-axis width was evaluated on a 20-scene
development set using masks with nominal widths of one, two, and three pixels.

The one-pixel masks produced the highest mean common-fragment \Fone{}. The
paired confidence interval for the difference between the one-pixel and
two-pixel masks included zero, so this comparison did not resolve a difference
at the 95\% level. The three-pixel masks produced a larger decrease whose
paired interval excluded zero.

These results indicate that a thin axis representation is preferable under
the tested configuration, particularly when the foreground becomes several
pixels wide.

    \centering
    \includegraphics[
        width=0.82\textwidth,
        height=0.68\textheight,
        keepaspectratio
    ]{figures/fig_width_sweep.pdf}
    \caption{%
    Development-only sensitivity to the nominal width of the binary
    filament-axis mask. Each thin line connects the same scene across mask
    widths of exactly one, two, and three pixels. Larger symbols show the
    density-stratified means and 95\% bootstrap confidence intervals.
    }
    \label{fig:width}
\end{figure}

\paragraph{Clean and degraded axis masks.}

The degraded one-pixel masks were also compared with the corresponding clean
procedural axes. The clean masks omit the modeled segmentation-like
imperfections, including small gaps and local raster irregularities.

Replacing the degraded masks with clean procedural axes produced a small
negative mean change whose paired confidence interval included zero. The
analysis therefore did not show a resolved aggregate improvement from removing
the modeled degradation.

At 30\% areal coverage, all four available development scenes showed lower
scores for the clean representation. However, four scenes are insufficient
for a reliable density-specific conclusion. This result should therefore be
treated as a conditional development diagnostic rather than evidence that
segmentation errors are unimportant.

    \caption{%

    }

\paragraph{Separating filament density from bundle width.}

The current prescribed areal-coverage levels are calculated from the union of
the thick rendered filament supports. Areal coverage can therefore increase
because the network contains more or longer filament centrelines, because the
rendered bundles are wider, or through a combination of these effects.

A more informative sensitivity analysis should vary the geometric network
density and the true rendered bundle width independently. This would separate
the effects of:

\begin{itemize}[leftmargin=1.5em,itemsep=2pt]
    \item total filament-centreline length per image area;
    \item the number of filaments and crossings;
    \item the physical or rendered bundle width;
    \item one-pixel axis coverage;
    \item thick-bundle areal coverage; and
    \item the number and length of mask interruptions.
\end{itemize}

\reviewnote{%
A factorial sensitivity study should be added here in which centreline-network
density and true bundle width are varied independently. The analysis should
report both one-pixel axis coverage and thick-bundle areal coverage so that
network complexity is not represented by one combined density measure. The
results are intentionally not included in this simplified review draft.
}

\subsection{Real SEM development case study}
\label{sec:res-real}

FilaSeg was also applied to one $512\times512$ crop from a real SEM image of a
dense CNT bundle network. The crop contains a manual reference annotation of
58 filament instances.

This crop informed method development and is therefore not a held-out test.
It does not provide an independent estimate of generalization or a population
confidence interval. All real-data observations in this manuscript are derived
from this single crop.

Figure~\ref{fig:qual-real} shows the final rendered output. Predicted instances
are assigned the colour of their one-to-one matched manual reference instance.
Unmatched predicted instances are shown in magenta, and the unmatched manual
reference instance is indicated by a dashed yellow outline.

The rendered instances are displayed because this figure illustrates the
delivered Stage~4 output. It should not be interpreted as an independent
validation of apparent-width accuracy or as the primary centreline-grouping
endpoint.
